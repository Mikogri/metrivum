# Local analyzer installation and library persistence

The accepted flow is a Windows installer downloaded from the web, explicit pairing with a loopback companion, local MotionTrace inference, then private cloud video/result storage. Existing historical results and native clients keep their contracts. No server GPU fallback is introduced.

Implementation:
1. Extend the companion with versioned discovery, authenticated readiness/job status and portable runtime configuration. Public discovery never exposes paths, tokens, videos or results. Keep exact Origin/Host checks and per-process pairing.
2. Package the existing offline Python environments with conda-pack, original model/license files, source `ai` and the published self-contained .NET bridge. Generate content hashes. A per-user Windows bootstrap installer verifies every asset before extraction and writes isolated local settings; no runtime dependency on developer paths or account credentials is introduced.
3. Add web connection/status/download controls. Treat unreachable as unknown installation state and abort polling/analysis on account changes.
   *Updated 2026-10-21:* pairing happens once. The analyzer keeps one token per computer in `%LOCALAPPDATA%\TrainFlowAnalyzer\pairing-token` and hands it to the configured origin through `POST /pair`; the browser keeps it in `localStorage` (`trainflow.localAnalyzer.token`). The installer registers `trainflow-analyzer://` so Start analysis can launch the analyzer. Deleting the token file unpairs every browser. Trade-off: a script running on the exact configured origin can obtain the token, which is no wider than what that origin can already do with a paired page.
4. After local inference, reuse Media upload/finalize and `/analyses/client-results` to persist the original video and result. Freeze a retry receipt so an interrupted save does not rerun ML or create duplicate analyses. Explicitly show upload/save failures and allow retry.
   *Updated 2026-10-21 (background queue):* analysis is no longer one browser request. The analyzer keeps up to 10 jobs (video + settings + owning user id) on disk and analyzes them one at a time; the browser may close. Any signed-in Metrivum page saves finished jobs through the same upload/finalize/client-results path, using the job id as the frozen receipt (idempotency key) and storing the uploaded media id with the job. The analyzer never holds a Metrivum session, so results finished while the browser is closed wait on disk and are saved on the next visit. Details: `tools/TrainFlow.LocalAnalyzer/README.md`.
5. Verify loopback access, pairing, cancellation, metadata, retry ordering and existing result validation/ownership rules. Packaging verification is separate from successful fresh GPU inference and public signing/distribution.

Runtime archives use [conda-pack relocation](https://conda.github.io/conda-pack/index.html), rather than copying environments with hard-coded development prefixes. The web cannot inspect installed programs directly. A reachable companion reports its protocol and readiness; an unreachable companion may be stopped, uninstalled, blocked or on another device.
