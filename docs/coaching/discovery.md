# Coach Discovery and specializations

`/app/discover` is available in Coach and Client perspectives. Search is authenticated, rate limited and restricted to onboarded adults. Coaches opt in through `PUT /api/v1/me/discovery`; withdrawal removes the listing on the next search and never needs a paid plan.

Coaching owns the English taxonomy: five ordered categories and 27 specializations, with separate category and specialization code namespaces. `GET /api/v1/coaching/specializations` returns the active dictionary. Categories organize choices and cannot be selected. Selections describe self-declared expertise, not verified qualifications.

`GET/PUT /api/v1/me/coaching-specializations` reads and replaces the authenticated coach's `selectedCodes`, `primaryCodes` and optimistic `version`. All plans allow zero to five distinct active selections, with up to three selected codes marked primary. Unknown/inactive codes, duplicates, invalid subsets and stale versions fail. The first save changes version 0 to 1. A shared module transaction commits the profile version, relational links and immutable change snapshot together. No route accepts another coach ID for updates. Public showcase and Discovery responses add `specializationSelections` with code, English name, category code and primary status.

Legacy free-text Discovery specializations and showcase competencies remain stored and editable. They are not automatically classified, converted or deleted. Existing profiles can remain empty and published eligible profiles remain visible in unfiltered searches.

Discovery accepts `specializations=code,code` with OR matching. SQL ranks by selected-specialization coverage, then specialization matches in text search, then current premium priority, then primary-match count and immutable coach ID. Higher coverage always wins over paid priority. Pro, Team and Studio share exactly one `premium_discovery` priority; Free and Starter share standard priority. Billing checks active periods and valid organizational seats on every search. Downgrade/expiry changes exposure without changing selections. Cards label paid placement as Featured. The legacy singular `specialization` filter remains supported, including legacy text.

Language, mode, location, text and offer filters compose before ranking and pagination. Accounts supplies active adult coach eligibility and permitted identity through `ICoachDiscoveryDirectory`; Offers supplies published offer previews through `IDiscoveryOffers`. Responses contain no contacts, client lists, birthdays, forms or check-ins. Existing profile/contact operations retain their own authorization.

Reads use batched owning-module contracts and page-bounded selection projections, without cross-module DbContexts or per-card queries. Candidate IDs still cross module boundaries in request batches; measure this cost for large directories before adding a search index. No persistent entitlement cache is used. Web text filters debounce for 250 ms; discrete filter selections remain immediate. Billing resolves personal and organizational priority in one UNION query. Empty candidate sets skip downstream reads; identity roles are grouped once, and showcase client counts share one aggregate.

The additive `CoachSpecializations` migration creates category/item dictionaries, versioned coach profiles, unique coach/code links and change history in `coaching`. It seeds stable English codes once through EF migration history and leaves old columns intact. It also adds a full relationship FK index to transfer requests. Apply only after verifying the development target/history and include the new tables in runtime grants. Unit tests cover dictionary/rules; `CoachSpecializationTests` and `CoachDiscoveryTests` require an explicitly disposable `TRAINFLOW_TEST_DATABASE`.
