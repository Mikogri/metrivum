# Stage 04 implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development and focused independent workstreams; integrate and review each slice before final verification.

**Goal:** Persistent notifications, separate Free/Pro platform billing, and truthful Analyze workspace.
**Architecture:** Extend existing modular monolith and billing ledger. Module-owned query providers expose aggregate contracts; notifications enlist in the shared ModuleTransaction. SignalR delivers hints, PostgreSQL remains authoritative.
**Tech Stack:** ASP.NET Core / EF Core / PostgreSQL / React Router / TypeScript.
**Spec:** `docs/coaching/stage-04-spec.md`

## Global constraints
- Preserve all pre-existing uncommitted work in this working directory; no bulk stage, commit, push or production deployment.
- Both plans expose all implemented capabilities; ownership, role and existing quantity limits remain.
- No new financial ledger parallel to existing Orders/Dues/Attempts/Payments/Transactions.
- Configured prices only; unset Pro price stays unconfigured. Simulated boundary only, never real funds.
- Module implementations reference other modules only through Contracts.
- EF migrations are authoritative. Apply only to confirmed dev project atclvdkpbccafakzpwls after inspecting identity/history.
- Existing chat UX remains: sound for incoming open-chat message, no open-chat bell item; automatic newest-chat selection.

## Audit findings
- Billing has immutable orders/payments/transactions, dues, simulated methods/provider and renewal worker, but requires saved method and does not distinguish platform sales.
- Access is centralized and configurable; there is no implemented platform plan catalog.
- Notifications are currently client-derived unread summaries, not durable history.
- Earnings is a currency-grouped total only. No Analytics module exists.
- Shared ModuleTransaction enlists module DbContexts and supports commit callbacks.
