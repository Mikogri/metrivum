# Remote MCP integration

Implement the supplied Stage 5 requirements in the existing API, using the official C# SDK 2.2.0 and stateless Streamable HTTP. Owning modules expose small application contracts; integrations never access their database contexts.

- Keep the collaboration file category filter next to search, with a compact responsive width.
- Add private integration connections, per-client grants, programming preferences, command receipts and immutable pending messages.
- Use Supabase OAuth authorization details for client identity and consent. Ordinary OAuth tokens cannot use the REST API as a shortcut around integration grants.
- Publish configured protected-resource discovery and enforce JWT identity, exact client connection, feature grants, resource policy and bounded tools.
- Expose real read operations and draft-only training/form writes. Never apply training changes to clients or send without an authenticated TrainFlow approval.
- Add Integrations/consent/approval UI using existing account lifetimes and generated contracts.
- Verify API/architecture, isolated PostgreSQL constraints and races, browser UI and an actual generic MCP protocol client. Apply additive migrations only to the previously confirmed development project after checking live history.

Public HTTPS addresses and Supabase OAuth settings are deployment prerequisites. Generic local protocol verification cannot establish ChatGPT/Claude connection or platform write eligibility; record each separately. No production deployment or embedded model runtime is part of this work.

Baseline: 219 backend unit tests passed before integration changes. Existing unrelated working-tree edits are preserved.
