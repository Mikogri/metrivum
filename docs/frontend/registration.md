# Registration

- Signup offers Client (default) or Coach. This is an onboarding preference carried in the confirmation URL, code-entry page and resend link; it is not an authorization claim. The authenticated onboarding API validates and assigns the selected role.
- Email confirmation remains enabled in the development Supabase project. Its Resend test sender accepts only the Resend account owner's exact email address. Localhost is supported; a verified sender domain is required to deliver to other recipients. Do not disable confirmation to work around delivery errors.
- Supabase may represent SMTP HTTP 500 responses as `AuthRetryableFetchError`. The UI distinguishes these service failures from requests without a response. Inspect Supabase Auth logs for delivery diagnostics; never display raw SMTP errors or credentials to users.
- Registration tests cover both roles, confirmation-code navigation, resend URLs, immediate-session environments and server/network error classification. They mock Auth and do not send email.
- A failed confirmation email (Supabase answers HTTP 500 "Error sending confirmation email") now shows its own message ("We couldn't send the confirmation email…") instead of the generic service error; the server text is only logged to the console in development. With the Resend test sender this happens for every address except the Resend owner's. Fix it in the dashboards, not in code: verify a sending domain in Resend, then set Supabase Auth → SMTP sender to an address on that domain.
- "Add another account" opens sign-in with a Sign in / Create account switch. Both keep the free slot; a new account never takes a slot that already holds another account.
- Onboarding has five steps: account, body (sex, height, weight, body fat), heart rate and recovery (HR max with an age estimate, sleep, stress), training (experience, activity, sessions, session length, days, equipment) and health and goals. Every step after the first can be skipped; only clients must give sex, height and weight. Skipping clears what was typed in that step.
- Passwords: 8–72 bytes, and not one of the most common passwords, not one or two repeated characters and not containing the email's name part. Also enable Supabase Auth's leaked-password protection.
